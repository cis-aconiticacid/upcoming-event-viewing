# upcoming_event_viewing

A local seminar/event calendar built on vdir + khal. Events from multiple sources are stored in a single vdir and surfaced via khal as a separate `seminars` calendar, isolated from the main personal calendar. Usually work with my planner

## Structure

```
upcoming_event_viewing/
├── vdir/        # ics files, one per event series or one-shot event
├── scripts/     # per-import scripts generated by AI, kept for reference
└── README.md
```

## khal integration

The vdir is mounted in `~/.config/khal/config` as a separate calendar:

```ini
[[seminars]]
path = ~/ai_tool/upcoming_event_viewing/vdir/
color = light green
readonly = no
```

To hide seminars from normal `khal list`, add to `~/.bashrc`:

```bash
alias khal='khal -d seminars'
```

To query seminars explicitly:

```bash
khal list -a seminars today 90d
```

## ICS fields

Each event stores the following fields:

| ICS field     | Notes                                          |
|---------------|------------------------------------------------|
| `SUMMARY`     | Event title                                    |
| `DESCRIPTION` | Free text, organizers, notes                   |
| `LOCATION`    | Room or Zoom link                              |
| `URL`         | Source page — stored but not displayed by khal |
| `DTSTART`     | First occurrence                               |
| `DTEND`       | End of first occurrence                        |
| `RRULE`       | Recurrence rule (RFC 5545), omitted for one-shots |

## Import

Events are imported manually. For each new source, provide a CSV and tell the AI the following — it will generate a one-off import script:

- CSV column names and what they mean
- `event_type`: `recurring` or `oneshot`
- `source_name` and `source_url`
- If recurring: semester start and end dates

### CSV format

The importer accepts CSVs with arbitrary column names. The mapping from columns to ICS fields is specified per import. Mapping supports:

- `{ColumnName}` — direct substitution
- `regex:{ColumnName}:pattern:group` — extract substring via regex
- `{DAY}` — converts day abbreviations (M/T/W/R/F) to RFC 5545 weekday codes (MO/TU/WE/TH/FR)

#### Example: recurring seminar table

CSV columns: `Seminar, Day, Time, Location, Organizers`

```
"Abelian Varieties Reading Seminar","M","3:30pm-5:00pm","Van Vleck B317","Tonghai Yang, ..."
```

Mapping:
```
SUMMARY     ← {Seminar}
LOCATION    ← {Location}
DESCRIPTION ← Organizers: {Organizers}
URL         ← <source_url>
RRULE BYDAY ← {DAY}
RRULE start ← regex:{Time}:^(\d+:\d+(?:am|pm)):1
RRULE end   ← regex:{Time}:-(\d+:\d+(?:am|pm))$:1
RRULE UNTIL ← <semester_end>
DTSTART     ← <semester_start> + first matching weekday
```

#### Example: one-shot event table

CSV columns: `Date, StartTime, EndTime, Title, Location, Description`

```
"Apr 7","12:00 pm","1:00 pm","ML+X Forum","","..."
```

Mapping:
```
SUMMARY  ← {Title}
LOCATION ← {Location}
DESCRIPTION ← {Description}
URL      ← <source_url>
DTSTART  ← {Date} {StartTime}
DTEND    ← {Date} {EndTime}
```

### Output

Each CSV row produces one `.ics` file in `vdir/`. Filename is a SHA1 of `(source_name, SUMMARY, DTSTART)`. Re-running an import with the same data overwrites the file in place.

## Adding to personal calendar

Browse seminars, then manually copy interesting ones to the main calendar:

```bash
khal list -a seminars today 90d
khal new -a <main_calendar_name> <date> <time> "<title>"
```
